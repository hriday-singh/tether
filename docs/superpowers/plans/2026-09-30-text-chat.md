# Text Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Room members can send and read plain-text chat messages in a sidebar tab. Messages persist, arrive live, and backfill after a reconnect.

**Architecture:** Chat rides the existing JSON control channel. `chat.send` (client) is stored in a new
`chat_messages` table with its own per-room gapless `seq`, then broadcast as `chat.msg`. History and
gap-fill use `GET /api/rooms/:id/chat`, which has the same page shape as `/events`. Chat never enters
the Yjs doc, so checksum and chaos invariants are untouched. A per-connection token bucket
(`CHAT_RATE_PER_SEC`/`CHAT_BURST`) keeps chat separate from the 5 frames/s edit throttle.

**Tech Stack:** Zod, Fastify 5, `ws`, `node:sqlite`, Next.js 16 / React 19, TanStack Query, Tailwind v4 tokens, Vitest + RTL.

**Spec:** `docs/11-decisions.md` ADR-017, `docs/04-protocol.md` (feed delivery rules reused), `docs/07-frontend.md`.

## Global Constraints

- TypeScript strict, no `any`. Files ≤ 700 lines. (`fake-sync-client.ts` is already 875 lines; add as little as possible there and do not grow the problem elsewhere.)
- Never commit. Never run migrations. `migrations/0002_chat.*.sql` are generated only. `SQLITE_INIT_SCHEMA` mirrors them because that is the existing dev bootstrap.
- Rebuild shared after edits: `pnpm --filter @tether/shared build:pkg`.
- UI uses tokens only (`bg-card`, `text-muted-foreground`, `text-caption`, `rounded-xl`, `transition-ui`, `presenceClass()`). No raw hex or px colors. Reuse `Button`, `Badge`, `Tip`, `Skeleton`, `Icon`. A new `Textarea` primitive goes in `components/ui/input.tsx`.
- `packages/sync-client` and `apps/web/lib/sync/server-sync-client.ts` belong to the connect-frontend work. Do not edit them here. Task 6 lists the handoff.

## Review Focus

1. Over-long or whitespace-only text: the composer blocks send at `CHAT_MAX_CHARS`. Otherwise the server's Zod parse would close the socket with 4009.
2. Resend after reconnect (same `rid`): the server returns the stored message, stores nothing new, and does not rebroadcast.
3. Spam from one tab: the 6th message inside the burst gets `error{code:'rate_limited'}`, the socket stays open, and edits are not throttled.
4. Markup in message text (`<img onerror>`): it renders as literal text, because React escapes it and chat never uses `dangerouslySetInnerHTML`.
5. Reconnect with missed messages: `chatSeq` from welcome drives the gap-fill loop, and nothing is duplicated.
